# ملاحظات تعليمية من مشروع FixFlow

FixFlow ليس مجرد CRUD تقليدي. الهدف منه أن يتعلم المطور بناء نظام Laravel عملي فيه أدوار، عزل بيانات، workflow، تقارير، واختبارات.

## Multi-tenancy

يتعلم المطور كيف يفصل بيانات الشركات باستخدام `company_id` في الجداول التشغيلية.

الأفكار المهمة:

- كل عميل وجهاز وطلب وقطعة وفاتورة مرتبطة بشركة.
- استخدام global scopes يقلل خطر نسيان فلترة `company_id`.
- في بعض التقارير نستخدم `withoutGlobalScope` ثم نطبق `company_id` صراحة حتى تكون الإحصائيات دقيقة.

## Authorization

يتعلم المطور الفرق بين إخفاء الأزرار وحماية النظام فعليًا.

الأفكار المهمة:

- Spatie Permission لإدارة roles وpermissions.
- Policies لحماية الموديلات.
- Middleware لحماية routes.
- التحقق من نفس الشركة داخل السياسات.
- الفني والعميل لديهما قواعد أضيق من الشركة.

## Workflow

يتعلم المطور بناء دورة حياة واضحة بدل تحديث status عشوائي.

الأفكار المهمة:

- الحالات معرفة داخل `ServiceRequestWorkflowService`.
- كل انتقال حالة له قواعد.
- الانتقالات غير المسموحة ترجع validation error.
- إغلاق الطلب يحدث ضمن منطق مركزي.
- يتم تسجيل تغييرات الحالة داخل `audit_logs`.

## Notifications

يتعلم المطور استخدام Laravel Notifications لحالات تشغيلية حقيقية.

الأمثلة:

- إشعار الفني عند تعيينه على زيارة.
- إشعار dispatcher عند وصول طلب جديد من عميل.
- إشعار العميل عند تغير حالة الطلب.

## PDF

يتعلم المطور توليد ملفات PDF من بيانات Eloquent وعرض Blade.

الأفكار المهمة:

- التقرير لا ينشأ إلا بعد اكتمال الطلب ووجود بيانات تقرير.
- ملف PDF يحفظ في storage.
- مسار الملف يحفظ في `service_reports.pdf_path`.

## QR

يتعلم المطور ربط الأجهزة بهوية قابلة للمسح.

الأفكار المهمة:

- كل جهاز يملك `qr_code` أو token.
- صفحة QR العامة تعرض بيانات محدودة.
- سجل الصيانة لا يظهر إلا لمستخدم مصرح له.

## Reports and Dashboards

يتعلم المطور بناء مؤشرات تشغيلية مفيدة بدل عرض أرقام عشوائية.

الأمثلة:

- الطلبات المفتوحة.
- الطلبات المتأخرة.
- أكثر أنواع الأجهزة طلبًا.
- أكثر الفنيين إنجازًا.
- قطع الغيار منخفضة المخزون.

الأفكار المهمة:

- لا نكتب queries داخل Blade.
- نستخدم Service مخصصة للتقارير.
- يمكن استخدام cache قصير لتخفيف الضغط.

## Testing

يتعلم المطور كتابة Feature Tests تغطي قواعد العمل المهمة.

الأمثلة:

- مدير الشركة لا يرى بيانات شركة أخرى.
- الفني لا يرى زيارة غير مسندة له.
- العميل لا يرى طلبات عميل آخر.
- يمكن إنشاء طلب صيانة.
- يمكن تغيير الحالة وفق workflow صحيح.
- لا يمكن الانتقال إلى حالة غير مسموحة.
- يمكن تعيين فني.
- يمكن إنشاء فاتورة من طلب مكتمل.

## Clean Architecture

يتعلم المطور توزيع المسؤوليات بشكل أوضح:

- Controllers تستقبل الطلب وتعيد response.
- Form Requests تتحقق من البيانات.
- Services تنفذ منطق العمل.
- Policies تقرر السماح أو الرفض.
- Models تحمل العلاقات والخصائص.
- Blade يعرض البيانات ولا يحتوي منطق قواعد العمل.

هذه البنية تجعل المشروع أسهل في الفهم، الاختبار، والتوسعة.
