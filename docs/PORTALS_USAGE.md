# استخدام بوابات FixFlow

يوفر FixFlow بوابتين تشغيليتين مهمتين:

- بوابة الفني: لإدارة الزيارات المسندة للفني وتنفيذ العمل الميداني.
- بوابة العميل: لمتابعة الأجهزة وفتح طلبات الصيانة ومراجعة الحالات والتقارير والفواتير.

## بوابة الفني

يدخل الفني عبر الحساب التجريبي:

- البريد: `technician@example.com`
- كلمة المرور: `password`

بعد تسجيل الدخول ينتقل الفني إلى `/technician/dashboard`.

### Dashboard

تعرض لوحة الفني:

- زيارات اليوم.
- الزيارات القادمة.
- الطلبات قيد التنفيذ.
- الطلبات التي تنتظر قطع غيار.

### My Visits

المسار: `/technician/visits`

تعرض الصفحة الزيارات المسندة للفني الحالي فقط، مع فلترة حسب حالة الزيارة والتاريخ.

الحماية الخلفية تعتمد على `role:technician` و`can:viewAny,ServiceVisit` و`can:view,serviceVisit`، لذلك لا يستطيع الفني الوصول إلى زيارة غير مسندة له حتى لو عرف رابطها.

### تفاصيل الزيارة

من صفحة تفاصيل الزيارة يستطيع الفني:

- رؤية بيانات العميل والجهاز ووصف المشكلة والعنوان.
- بدء الزيارة.
- حفظ الملاحظات الفنية.
- تسجيل التشخيص `diagnosis`.
- تسجيل الحل `solution`.
- إضافة قطع الغيار المستخدمة.
- رفع صور قبل وبعد الصيانة عند الحاجة.
- إنهاء الزيارة وإغلاق الطلب.

عند إنهاء الزيارة ينشئ النظام تقرير صيانة، ويسجل القطع المستخدمة، وينقل الطلب إلى `completed` عبر `ServiceRequestWorkflowService`.

### مثال عملي للفني

1. يتم تعيين الفني على طلب: "Conference room AC is not cooling".
2. تظهر الزيارة في لوحة الفني وفي صفحة My Visits.
3. يفتح الفني تفاصيل الزيارة ويراجع بيانات العميل والجهاز والعنوان.
4. يضغط "بدء الزيارة"، فينتقل الطلب من `scheduled` إلى `in_progress` إذا كان مجدولًا.
5. يضيف التشخيص والحل والقطع المستخدمة.
6. يضغط "إنهاء الزيارة وإغلاق الطلب".
7. يتم تسجيل التقرير وإضافة الأحداث إلى `audit_logs`.

## بوابة العميل

يدخل العميل عبر الحساب التجريبي:

- البريد: `customer@example.com`
- كلمة المرور: `password`

بعد تسجيل الدخول ينتقل العميل إلى `/customer/dashboard`.

### Dashboard

تعرض بوابة العميل:

- عدد أجهزته.
- عدد طلباته المفتوحة.
- آخر حالات الطلبات.

### أجهزتي

المسار: `/customer/assets`

تعرض الصفحة أجهزة العميل الحالي فقط، مع حالة الضمان:

- ساري حتى تاريخ محدد.
- منتهي.
- لم يبدأ بعد.
- غير موثق.

### إنشاء طلب صيانة

المسار: `/customer/service-requests/create`

يستطيع العميل إنشاء طلب جديد عبر اختيار جهاز من أجهزته فقط، ثم كتابة عنوان المشكلة ووصفها وتاريخ الزيارة المفضل والأولوية.

ينشأ الطلب بحالة `new` ويتم إرسال Notification إلى مستخدمي `dispatcher` داخل نفس الشركة.

### طلباتي

المسار: `/customer/service-requests`

تعرض الصفحة طلبات العميل الحالي فقط، وتشمل الحالة، الأولوية، الجهاز، Timeline، التقرير النهائي إذا وجد، والفاتورة إذا وجدت.

### مثال عملي للعميل

1. يدخل العميل إلى بوابته.
2. يفتح "أجهزتي" ويتأكد أن جهاز المكيف داخل الضمان.
3. يضغط "طلب صيانة جديد".
4. يختار جهاز المكيف ويكتب: "المكيف لا يبرد جيدًا".
5. يرسل الطلب.
6. يظهر الطلب في "طلباتي" بحالة `new`.
7. عند تغير الحالة تظهر الأحداث في Timeline.
8. بعد الإغلاق يرى العميل التقرير النهائي والفاتورة إن وجدت.

## شرح الصلاحيات ببساطة

- الفني لا يرى إلا الزيارات التي يكون `technician_id` فيها مساويًا لحسابه.
- الفني لا يستطيع عرض أو بدء أو إنهاء زيارة غير مسندة له.
- العميل لا يرى إلا الأجهزة والطلبات المرتبطة بسجل `Customer` الخاص بحسابه.
- العميل لا يستطيع إنشاء طلب على جهاز يخص عميلًا آخر.
- كل البيانات التشغيلية مرتبطة بـ `company_id` حتى تبقى بيانات كل شركة معزولة.
